A2. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------

**Problem Statement**

Saya, Arif, coding 5-6 jam sehari di VS Code sambil dengar musik. Ada tiga
hal yang konsisten mengganggu flow saya:

1. **Skip lagu butuh Alt-Tab.** 4-5 kali per jam. Setiap kali, cursor di
   VS Code hilang posisi, saya harus re-focus. Ini ganggu flow state.

2. **Saya tidak tahu apa yang diputar.** Kalau tidak buka Spotify, saya
   lupa lagu apa yang sedang main. Kadang saya dengar lagu yang tidak
   saya suka selama 3 menit sebelum sadar.

3. **Saya kebablasan di IG/YouTube saat nunggu async task selesai.**
   Ini yang paling parah. Saya jalankan OpenCode di terminal, atau E2E
   test, atau Cline — semuanya butuh 3-10 menit. Saya bosan, buka IG.
   Scroll. Kebablasan 30-45 menit. Lupa proyek. Setelah sadar, saya
   merasa bersalah. Siklusnya berulang tiap hari.

Selain itu, saya juga sering kebablasan scroll IG/YouTube **tanpa alasan
yang jelas** — bukan sambil nunggu apa-apa, murni karena bosan atau
menghindari task yang susah. Saya baru sadar setelah 1-2 jam hilang.

**Solution Overview**

WinNotch = kapsul kecil di atas layar yang **tahu apa yang saya kerjakan,
berapa lama, dan kapan async task selesai.**

Komponennya:

- **Media awareness:** hover expand untuk kontrol musik, Title Peek
  1.5s saat lagu ganti (tanpa hover), Pin State untuk interaksi tenang.
- **Async task awareness:** OpenCode / Cline / E2E test / manual long
  command selesai → notch kasih sinyal marquee 1.5s. Tidak perlu balik
  ke terminal untuk cek.
- **Time awareness:** di IG/YouTube window (bukan fullscreen) → tiny
  timer di ikon kapsul. 20 menit → normal. 40 menit → orange. 60 menit
  → red + pulse. Zero interruption, glanceable.
- **Fullscreen awareness:** nonton Netflix/anime fullscreen → notch
  hidden (tidak ganggu immersion). Exit → summary card 3s: "Netflix
  2j 15m. Mau break 5 menit?" — auto-collapse, zero judgement.
- **Gaming escape:** config "gaming_apps" → nol notifikasi, nol tracking.
  Gaming fully respected.

**Value Proposition**

Nusa (kompetitor utama) fokus pada utility hub: Pomodoro, water reminder,
file shelf, lyrics, timer. Bagus, tapi bukan yang saya butuhkan.

WinNotch fokus pada **awareness yang fragmented di 4 tools berbeda**:

- RescueTime → tracking, tapi tidak real-time, tidak di notch.
- ActivityWatch → tracking, tapi tidak ada notifikasi.
- ntfy / terminal-notifier → notifikasi async, tapi tidak aware konteks.
- Windows Task Manager → tahu proses, tapi bukan user-facing.

**WinNotch menyatukan 4 fungsi ini di satu titik glanceable di atas
layar.** Media + async task + time awareness. Tidak ada kompetitor yang
melakukan ketiganya sekaligus.

**Target Users**

- **Primary: saya sendiri.** Developer yang coding 5-6 jam/hari sambil
  dengar musik + pakai AI agent + rentan kebablasan di social media.
- **Secondary: power user Windows lain** dengan pola sama — developer,
  peneliti, writer, siapa pun yang: (a) sering Alt-Tab untuk skip lagu,
  (b) pakai async task (AI agent / build / test), (c) rentan sosial
  media scrolling tanpa sadar.

**Honest Acknowledgment**

- Nusa (~45k download, native Rust, ~30 MB RAM) sudah jadi produk
  matang di space "media notch". WinNotch **tidak** mencoba mengalahkan
  Nusa di fitur atau RAM mentah. Kami fokus di **awareness layer** yang
  Nusa tidak punya.
- Title parsing untuk deteksi browser (IG vs YouTube vs Google Docs)
  hanya **~90% akurat**. Bukan untuk billing, hanya untuk awareness.
  Browser extension = v1.1 kalau perlu lebih akurat.
- WSL shell hook butuh user edit `.bashrc` (1 line, di-setup otomatis
  oleh installer).

A3. OBJECTIVES & SUCCESS METRICS
--------------------------------------------------------------------------------

**Primary Objectives**

1. Deliver frameless, transparent, always-on-top capsule overlay dengan
   hit-testing yang precise dan hover animation yang fluid.
2. Integrate Windows SMTC untuk media awareness (metadata + control).
3. Deliver **awareness layer** yang Nusa tidak punya: async task
   notification + time tracking + fullscreen summary.
4. Maintain "feel ringan": CPU ~0% idle, startup < 1s, no memory growth.
5. Deliver portfolio-grade process: UX Contract, Decision Log, Phase 0
   Spike with kill criteria.

**Success Metrics (Measurable)**

| Metric | Target | Acceptance |
|--------|--------|-----------|
| RAM idle (total, all processes) | < 100 MB typical | Task Manager 10 min idle |
| RAM with tracking + animation | < 130 MB | During marquee + tracking active |
| CPU idle (no animation) | ~0% | Task Manager 10 min idle |
| CPU during tracking + marquee | < 3% | Task Manager |
| Startup time | < 1s | Tray click → capsule visible |
| Media control latency | < 100 ms | Click → command executed |
| Hover expand delay | < 80 ms | Stopwatch / DevTools |
| Hover leave debounce | 150–200 ms | No flicker on rapid in/out |
| Foreground poll interval | 2-5 s | Configurable |
| Title parsing accuracy (browser) | ~90% | Manual test 20 sessions |
| Async notification latency (shell → notch) | < 500 ms | Shell exit → marquee visible |
| Fullscreen summary appear delay | < 1s after exit | Stopwatch |
| Soak test 24h memory delta | < 10% | Task Manager before/after |
| Multi-session SMTC | Correct | Test Spotify + Edge + VLC |

**Non-targets (honest)**

- RAM < 30 MB (Nusa achieves this; Tauri+WebView2 cannot match).
- Title parsing 100% accurate (browser extension needed).
- Battery impact = zero (WebView2 GPU wake-up on animation is real).
- WSL tracking tanpa shell hook (technically impossible from Windows).

**US1 — Skip lagu tanpa Alt-Tab**

AS Arif, coding 5-6 jam sehari dengan Spotify playing
I WANT to skip songs without Alt-Tab and without losing cursor position
SO THAT I don't break flow state 4-5 times per hour

Acceptance:
- [ ] Hover capsule < 80ms expand
- [ ] Click next → lagu skip < 100ms
- [ ] Focus window (VS Code) unchanged
- [ ] Cursor position in VS Code unchanged (U3)

**US2 — Glanceable tanpa hover**

AS Arif, fokus coding dan tidak mau terganggu
I WANT to see the new track title without hover
SO THAT I stay in flow dan tahu lagu berubah

Acceptance:
- [ ] Track change → capsule stays collapsed
- [ ] Marquee title 1.5s (F023)
- [ ] Then returns to icon (♪)
- [ ] Capsule does NOT auto-expand (respects U4)

**US3 — Pin untuk interaksi tenang**

AS Arif, mau baca lirik atau klik tombol dengan tenang
I WANT to pin the capsule expanded
SO THAT it doesn't collapse while I move the mouse

Acceptance:
- [ ] Click capsule → pin (S4)
- [ ] Mouse leave → does NOT collapse
- [ ] ESC / re-click → unpin

**US4 — Async task selesai tanpa cek terminal**

AS Arif, menunggu OpenCode / E2E test / Cline selesai
I WANT a notification saat task selesai
SO THAT saya tidak perlu bolak-balik cek terminal

Acceptance:
- [ ] WSL shell hook terpasang (1 line di .bashrc, auto by installer)
- [ ] Async task selesai → marquee 1.5s di kapsul: "OpenCode done — 4m 32s"
- [ ] Latency < 500ms dari shell exit ke marquee visible
- [ ] Manual long command (npm build) → juga trigger
- [ ] Tidak ada notification kalau task < 10s (tidak ada gunanya)

**US5 — Sadar berapa lama di IG/YouTube**

AS Arif, scroll IG/YouTube tanpa sadar

- [ ] 40 menit → orange

AS Arif, nonton anime fullscreen

A8. UX CONTRACT (U1–U8)
--------------------------------------------------------------------------------

| ID | UX Must-Feel | Validation |
|----|--------------|-----------|
| U1 | Never "stuck" on screen — user always knows how to dismiss | Tray visible; ESC = unpin; right-click menu |
| U2 | Hover feels instant, not waiting | Expand < 80ms; leave delay 150-200ms |
| U3 | No focus stealing while user is typing | Focused window unchanged on expand/click |
| U4 | Idle state truly passive (no blinking, no constant animation) | Nothing moves when no media + no tracking event |
| U5 | Error states don't panic user | SMTC failure → idle; WSL disconnect → silent log |
| U6 | First-run clarity | Tooltip + WSL setup wizard, once each |
| U7 | Personal feel test (15 min real use) | Log friction points |
| **U8** | **Awareness tidak pernah "muncul tiba-tiba"** | Tiny Timer = ikon berubah, zero expand/marquee/suara. Async notify = marquee 1.5s (yang user tunggu, bukan interrupt). Fullscreen summary = setelah exit, auto-collapse 3s. |

**Anti-Creep Rule**

Kalau UX polish konflik dengan timeline, kurangi animasi — JANGAN
tambah fitur. UX = "tidak ada yang mengganggu", bukan "paling banyak
gerakan". U8 adalah pembeda utama: awareness tanpa interruption.

A9. NON-FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------------------------

**Performance**

- RAM idle: < 100 MB total working set (WebView2 + tracking daemon).
- RAM during tracking + marquee: < 130 MB.
- CPU idle: ~0% when no animation.
- CPU during marquee/hover: < 2%.
- CPU during tracking (polling foreground): < 1%.
- Startup: < 1s.
- Media control latency: < 100ms.
- Foreground poll: 2-5s interval (configurable).
- Animation: 60 FPS, GPU-accelerated only.
- Soak test: 24h no crash, memory delta < 10%.

**Security**

- No network access at runtime (SMTC + foreground tracking = local only).
- WSL shell hook: localhost HTTP dengan **token auth** (generated at install, stored in config). Port tidak open ke network.
- No telemetry, no cloud sync.
- config.json local only.

**Reliability**

- 24h soak test, no crash, memory delta < 10%.
- Config atomic write (temp + rename).
- WSL hook: idempotent (kalau Notch down, task tetap jalan; hook silently log).

**Usability**

- Responsive: 1080p, 2K, 4K; DPI-aware.
- Contrast ≥ 4.5:1 for text.
- Keyboard: click capsule = toggle, ESC = collapse.
- First-run: tooltip + WSL setup wizard.

**Honest Non-Targets**

- Cannot match Nusa's ~30 MB RAM.
- Title parsing ~90% accurate (tidak 100%).
- Battery impact = not zero (WebView2 GPU wake).
- WSL tracking butuh user setup shell hook (1 line).

A12. RISKS & MITIGATION
--------------------------------------------------------------------------------

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| Hit-testing region-based unstable | High | High | Phase 0 Spike (5 days). Fallback: capsule-sized window tanpa transparent margin. |
| RAM > 130 MB dengan tracking | Medium | Medium | Foreground poll 5s (bukan 2s). Config minimum. Drop F034 kalau RAM tidak aman. |
| Title parsing akurasi < 85% | Medium | Medium | Test manual 20 sessions. Kalau < 85%, tawarkan browser extension sebagai opt-in (v1.1). |
| WSL hook fragile (Bash version, Shell startup lag) | Medium | Medium | Setup wizard + fallback ke manual edit. Log warning. |
| WSL tidak terinstall | Medium | Low | F032/F033 gracefully disabled. Notch tetap berfungsi untuk media + awareness dasar. |
| Fullscreen false-positive (Netflix di window) | Medium | Low | Test matrix: Chrome fullscreen, YouTube fullscreen, Netflix app. Summary card opt-in. |
| Tracking false-positive (VS Code window title = "Instagram" karena buka file instagram.js) | Medium | Medium | Regex whitelist strict. Log every categorization. Config custom patterns. |
| User merasa "diawasi" | Medium | High | Config default: **tracking off untuk v1.0**. Opt-in eksplisit. README jelas: "ini untuk kamu, bukan untuk kami". |
| WSL hook security (local port open) | Low | High | Token auth. Port random. Bind ke 127.0.0.1 only. |
| Battery drain dari tracking polling | Medium | Medium | Poll 5s, bukan 2s. Config interval. |

**Major risk yang perlu di-highlight: USER FEELING WATCHED.**

Ini bukan technical risk, tapi **ethical risk**. Kalau user merasa ini spyware, project gagal. Mitigasi:
- **Default: awareness OFF di v1.0.** User harus explicit enable di config.
- README jelas: "data tidak keluar dari laptop. Semua local."
- Dashboard (v1.1) akan show exactly apa yang dilacak.
- No upload, no telemetry, no analytics.

A13. WHAT V1 SOLVES / DOESN'T SOLVE
--------------------------------------------------------------------------------

**Solved di V1:**

1. **Skip lagu tanpa Alt-Tab** → F001+F002+F003
2. **Glanceable tanpa hover** → F023 (Title Peek)
3. **Async task selesai → notified** → F032+F033 (WSL hook)
4. **Sadar berapa lama di social** → F034 (Tiny Timer)
5. **Fullscreen tidak ganggu, tapi aware** → F008 + summary card
6. **Gaming fully respected** → F035 (gaming_apps config)

**NOT solved di V1:**

1. **Title parsing 100% akurat** → butuh browser extension. v1.1 (F036).
2. **Detailed time report (harian/mingguan)** → butuh persistent storage. v1.1 (F037).
3. **Custom thresholds per app** (misal IG = 15 min, YouTube = 30 min) → v1.1 (F038).
4. **Tracking di native apps** (WhatsApp desktop, Telegram) → title parsing Win32 workable, tapi tidak seakurat browser. v1.1.
5. **App categorization yang sangat akurat** → Win32 heuristic + config. v1.1 bisa tambah database app names.
6. **Battery impact zero** → tidak mungkin dengan WebView2. Honest.

**Explicitly not solved ever:**

- **Parental control / screen time enforcement.** WinNotch = awareness, bukan nanny.
- **Billing-grade time tracking.** ~90% accuracy cukup untuk awareness, tidak untuk billing.
- **Cloud sync.** Offline-first by design.

**Filosofi V1:**

V1 menyelesaikan **3 masalah utama** (media + async + social scrolling)
dengan solusi yang **jujur, personal, dan tidak mengganggu.** Yang tidak
solved → v1.1+ dengan alasan jelas. Tidak ada overclaim.

C6. SECURITY POSTURE

(Tetap sama + WSL hook security.)

WSL Hook Security (New)

Port: 127.0.0.1 only (bind explicit, tidak ke 0.0.0.0)

Token: UUID v4 generated at install, stored in config.json

Auth: X-Notch-Token: <uuid> header required on every POST

Rate limit: 100 req/min per token (prevent spam)

Payload validation: JSON schema, max 1KB

No data persistence: notifications are transient, not logged to disk

Kalau token leaked: user regenerate via config + restart

Privacy Note (README)

"Semua tracking adalah local. Tidak ada data yang dikirim keluar."

"Config file berisi app names yang dilacak — kamu bisa lihat apa yang dilacak."

"Tidak ada network call selain localhost WSL hook."

C8. FOREGROUND TRACKING (F030-F035)

F030 — Foreground Poll

Interval: 5s default (config: 2-5s).

API: windows crate GetForegroundWindow + GetWindowTextW.

Extract: process.exe + window_title.

Emit session_changed event on change.

Title Parsing Strategy

For browser windows: window title = "Page Title - Browser Name".
Extract page title.

Match against regex patterns from config (case-insensitive).

Order: gaming_apps (exact exe) → work_whitelist (exact exe) →
social_apps (regex) → streaming_apps (regex) → unknown.

F031 — Session Timer

Track (app_id, start_time) in memory.

Reset on change.

Emit timer_threshold when crossing 20/40/60 min.

Reset at day boundary (midnight) or on user logout.

F034 — Tiny Timer Display

Only when category = social AND foreground app is browser.

Frontend shows timer in S1 icon (replaces ♪/•).

Color: white (0-19), orange (20-59), red (60+).

Pulse 1x on red transition.

F035 — App Categorization

Config-based rules (lihat C4 schema).

Fallback: unknown category (no tracking, no timer).

User can extend via config.

False-positive handling

Title "instagram.js - Visual Studio Code" → whitelist Code.exe prevents false trigger.

Test case: 20 manual sessions, log every categorization.

Kalau akurasi < 85%, README jelas: "Title parsing heuristic, bisa salah."

C9. WSL SHELL HOOK (F032)

Setup

Installer akan:

Generate token (UUID v4).

Save to config.

Print 3 lines to paste into .bashrc.

User paste:

bash
# WinNotch async task notify
__notch_notify() {
  local exit_code=$?
  local duration=$SECONDS
  if [ $duration -gt 10 ]; then
    curl -s -X POST "http://127.0.0.1:9182/notch/notify" \
      -H "X-Notch-Token: $(cat ~/.winnotch-token)" \
      -d "{\"source\":\"$1\",\"duration_seconds\":$duration,\"exit_code\":$exit_code}" \
      > /dev/null 2>&1
  fi
}

__notch_wrap() {
  local source=$1
  shift
  local start=$SECONDS
  "$@"
  local exit_code=$?
  local duration=$((SECONDS - start))
  if [ $duration -gt 10 ]; then
    curl -s -X POST "http://127.0.0.1:9182/notch/notify" \
      -H "X-Notch-Token: $(cat ~/.winnotch-token)" \
      -d "{\"source\":\"$source\",\"duration_seconds\":$duration,\"exit_code\":$exit_code}" \
      > /dev/null 2>&1
  fi
  return $exit_code
}
Usage

opencode run "..." → wrapped via alias: alias opencode='__notch_wrap opencode opencode'

Manual: __notch_wrap build npm run build

E2E: __notch_wrap e2e npm run test:e2e

Limitation

Hanya works untuk commands yang di-wrap.

Auto-wrap known commands via .bashrc aliases (opencode, cline, npm, cargo).

Commands unknown but long (misal python script) → user wrap manual.

Fallback (if shell hook too fragile for user)

v1.1: better integration via process monitoring dari Windows.

v1.1: CLI tool notch-notify yang bisa dipanggil dari mana saja.

D3-13 (2026-10-28) — Title Parsing via Win32 (Bukan Browser Extension)

Decision: V1 pakai Win32 GetWindowText + regex patterns. Browser
extension = v1.1 (F036).

Rationale:

Browser extension = additional development + user friction (install
extension per browser).

Win32 parsing = ~90% accuracy, cukup untuk awareness (bukan billing).

Config-based regex patterns = user dapat customize sendiri.

Kalau akurasi < 85% di Phase 0, reconsider.

Honest limitation:

Tidak 100%. Custom page title = miss.

Native apps (WhatsApp desktop, Telegram) = less accurate.

Documented in A13.

D3-14 (2026-10-28) — WSL Shell Hook with Token Auth

Decision: WSL async task notification via shell hook + localhost HTTP
dengan token auth.

Rationale:

WSL jalan di Linux subsystem, tidak bisa dimonitor dari Windows
process list.

Shell hook = 1 line di .bashrc, setup wizard otomatis.

Token auth = prevent spam dari proses lain.

Security:

Bind 127.0.0.1 only

Rate limit 100/min

Payload max 1KB

Fallback:

Kalau user tidak punya WSL → F032/F033 gracefully disabled.

Kalau shell hook fragile → v1.1 alternative (process monitor).

Risk acknowledged:

User friction (edit .bashrc, walau auto by installer).

Bash version differences (mitigate: setup wizard checks).

D3-15 (2026-10-28) — Fullscreen: Hidden + Summary on Exit

Decision: Fullscreen → capsule hidden total (tidak ganggu immersion).
Exit → summary card 3s.

Rationale:

Opsi "compact visible saat fullscreen" akan ganggu HUD game + subtitle.

Opsi "never hide" = tidak bisa main game/nonton dengan tenang.

Summary on exit = aware setelah, tanpa ganggu during.

Gaming = total escape via config gaming_apps.

User comfort:

Zero judgement dalam summary ("kamu terlalu lama" → NO).

Auto-collapse 3s (tidak perlu klik).

[break 5 menit] = optional, user choice.

Rationale:
